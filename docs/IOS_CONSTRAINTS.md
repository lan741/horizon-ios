# iOS 上到底能不能「跑 Java」——先把边界钉死

这一页是设计前提，不是免责声明。它决定了整个项目为什么长成现在这样。

## 1. 没有 JVM，也不允许自带

iOS 不提供 `java`、`libjvm`、`dalvik`。想跑 JVM 只有两条路：

1. 把 JVM（HotSpot / OpenJDK）编译成静态库嵌进 app —— 它需要
   `mmap(PROT_EXEC)` 生成 JIT 代码、需要信号处理做 safepoint、需要
   `fork/exec` 之外的自举路径。前两条在 iOS 上直接撞上硬限制。
2. 写解释器 —— 可以，纯 C/Rust 解释器不违反任何规则（不生成可执行页）。
   但它要重新实现 2 万个类的语义，且性能比原版低一个数量级。

Horizon（桌面版）走的是第三条路：**把 Java 语义改写成 Rust**，Java 只在构建期参与。

## 2. 关键系统限制（iPadOS 27）

| 限制 | 后果 |
|---|---|
| 禁止 `fork` / `exec`（`posix_spawn` 仅限 Apple 私有 entitlement） | 不能像桌面启动器那样「调用 java 进程」 |
| 禁止可写+可执行内存（无 JIT，除非用 JSC 的 entitlement，且不适用于第三方 JVM） | 动态翻译/热编译路线出局 |
| 应用沙盒 + 数据保护 | 只能读写用户通过文件选择器授权的文件与自己容器内的文件 |
| 后台执行受限 | 编译大 jar 必须在前台完成，中断要能续 |
| 代码签名 | 任何「下载后执行」的路径都走不通（这也是 App Store 2.5.2 的红线） |

## 3. 因此本项目的分工

```
┌───────────────────────── iPad（设备内） ─────────────────────────┐
│ 用户选择 client.jar                                              │
│   ↓ hz_core::zipfile + inflate（自研，无三方库）                  │
│   ↓ hz_port：blockstates / models / textures / lang / data        │
│   ↓ 写出 .hzp（单文件、按名索引、零解析）                          │
│   ↓ hz_game：Rust 引擎（区块、物理、剔除、出帧）                   │
│   ↓ hz_ffi → Swift → Metal                                      │
└──────────────────────────────────────────────────────────────────┘
                     ↑ 不含任何 Mojang 二进制
┌──────────────────── Mac / CI（离线） ────────────────────────────┐
│ hz classes → 调用图、字节码体量、热点目标                          │
│ hz stubs   → 每类一个 Rust 模块（带 JVM 描述符与 todo!()）         │
│ 人或编码代理逐类补全 → 合回 hz-game                                │
└──────────────────────────────────────────────────────────────────┘
```

## 4. 为什么「数据编译」不是偷懒

Minecraft 的可玩性大部分来自数据而不是代码：

- 方块外观 = `blockstates/*.json` + `models/**/*.json` + 贴图
- 物品/配方/战利品/世界生成 = `data/**/*.json`
- 文本 = `lang/*.json`
- 声音索引 = `sounds.json`

把这些在导入时编译成原生结构，运行时就只剩「查表 + 画三角形」。原版每次启动都要解析上万个 JSON，
这里一次编译、之后零解析——这也是 `.hzp` 存在的理由。

剩下真正需要代码的（实体 AI、红石、区块生成算法、附魔结算……）必须逐类移植，
工具负责把工作量算清楚，不假装能一键完成。

## 5. 对用户的诚实承诺

- 联网只用于**下载游戏版本**（`app/HorizonPad/Engine/VersionDownloader.swift`），走 HTTPS，
  没有任何自有服务器，也不上传用户的 jar 或世界。`Info.plist` 里不需要
  `NSAppTransportSecurity` 放宽，因为两个源都是 TLS；iOS 上 `URLSession` 也不需要额外
  entitlement。导入本地 jar 的路径仍然完全离线。
- 应用**不上传**：诊断日志只有用户点「导出」才会离开沙盒。
- 应用**不包含**游戏资源：装完之后什么资源都没有，必须由用户导入自己的 jar。
- 覆盖度报告会明确写出「还有多少个 Java 类没有对应实现」，不用完成度百分比糊弄。
